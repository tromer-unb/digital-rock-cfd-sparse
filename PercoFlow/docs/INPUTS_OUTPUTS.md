# Inputs and outputs

## Images (`percoflow image`)

Any 2D segmented image readable by Pillow (PNG, TIFF, JPEG, BMP) or a NumPy `.npy` boolean array.

| rule (`image.pore_rule`) | pore pixel | when to use |
|---|---|---|
| `green` (default) | G ≥ 80 and G ≥ R + 30 and G ≥ B + 30 | RGB(A) masks with pores labelled in pure green. An image without any green pixel falls back to `threshold`. |
| `threshold` | grey > `image.threshold` (default: mid-range) | grey-scale segmentations, bright pores |
| `nonzero` | grey > 0 | binary masks (0 = solid) |

`image.invert: true` swaps the phases (dark pores). Pore objects smaller than `min_object_size` (20 px, 8-connected) are
removed. Lengths are in **pixels**; `k_D` is in px². Convert with the measured pixel size `a`:
`k[m²] = k_D[px²]·a²` (`percoflow.descriptors.to_si`).

Orientation: `--direction lr` (flow left → right, inlet = first column after cropping) or `tb` (top → bottom, inlet = first
row). Run both for the two principal directions of a sample; the anisotropy ratio is `max(k)/min(k)`.

Window: bands of `domain.band_fraction` (8 %) of the side are removed at the inlet and outlet sides. **The permeability of a
window is a property of that window**: on heterogeneous images k can change markedly with the band width, and a sample can
stop percolating when the band changes. Scan the band (`--band`) or analyse several windows before reporting one number per
sample.

## Meshes (`percoflow mesh`)

A 2D triangle mesh readable by meshio/scikit-fem (Gmsh `.msh` 2.2/4.1 recommended) with physical groups:

| group | dimension | meaning |
|---|---|---|
| `FLUID` | 2 | fluid surface (optional name) |
| `INLET` | 1 | p = p_in (pressure-driven) |
| `OUTLET` | 1 | traction-free |
| `WALLS` | 1 | no-slip |

Every boundary curve must belong to exactly one of INLET, OUTLET, WALLS. `--direction` gives the main flow axis (used for
`L`, `W` and the velocity inlet). `k = μ Q L/(W ΔP)` with flux-weighted pressures on INLET and OUTLET; `L` and `W` default to
the bounding-box extents along and across the flow and can be set with `--length`/`--width`. Example: `examples/obstacles.msh`
(generated by `examples/make_examples.py`, which shows how to name the groups with the Gmsh Python API).

## Configuration

All options with their defaults and meaning: `examples/config_default.yaml` and `src/percoflow/config.py`. A typo in a key is
an error, not a silent default. The command-line options override the file.

## Run directory

| file | content |
|---|---|
| `manifest.json` | full configuration, SHA-256 of inputs and outputs, package version + git commit, library versions, OpenFOAM version, host, UTC times, command line, notes (e.g. cross-check disabled) |
| `result.json` | `percolation` (cluster counts, χ_c), `critical_throat_width_px`, `permeability` (k_D, Q, ΔP, L_s, W, b, alternative definitions, reservoir pressure share), `solver` (unknowns, residual, mass imbalance, energy identity, times, MINRES iterations), `mesh`, `descriptors`, `openfoam_crosscheck` |
| `mask_selected.png` | the analysed percolating domain (white) |
| `mesh/mesh.msh` | FE mesh, Gmsh 4.1, padded frame |
| `fields.npz`, `fields.vtu` | vertex velocity, pressure, speed (open the `.vtu` in ParaView) |
| `fields.png` | pressure and speed maps |
| `openfoam/openfoam_crosscheck.json` | FV vs FE per window, convergence diagnostics; case folders kept with `openfoam.keep_cases: true` |

`percoflow verify <run_dir>` recomputes every output hash listed in the manifest.
